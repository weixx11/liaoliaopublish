# 料小宝用户监控：下一阶段

2026-11-04从官网 `https://home.liaoxiaobao.cn/main.dart.js` 中发现以下只读调用，并使用当前已保存会话实测成功。已完成接口读取、最近发布时间排序及连续两轮去重检查，现已通过 `liaoxiaobao_monitor_adapter.py` 接入统一工具。独立测试脚本仍可单独运行，正式程序不导入测试脚本。

| 接口 | 方法 | 加密前参数 | 前端读取 |
|---|---|---|---|
| `/user/profile` | POST | 空对象 | userId、nickname、avatar、phone、email、userType等 |
| `/follow/counts` | POST | 空对象 | followCount、fanCount、blockCount、authorBlockCount、newToday |
| `/follow/list/{page}/{size}` | POST | blocked=false，可选keyword、authorId | current/pages/records/size/total |
| `/article/list/{page}/{size}` | POST | followedOnly=true，可选authorId、keyword | data.records |

前端文章列表默认每页15条、关注管理页每页20条，另有关注列表1/100调用。不得把 `/article/list` 无页码接口当查询：前端该路径用于批量上架（articleNos参数），是写入操作。也不调用follow/follow、follow/unfollow等修改关注接口。

## 测试顺序

当前已完成下面第1至3步的只读请求。关注商家唯一标识为authorId，名称字段包括authorNickname、authorRemarkName、name、remark等；响应分页为current/pages/records/size/total。文章接口可返回100条，实测authorId匹配请求、第一页isListed=true且status=1。

文章保留id与articleNo，显示字段为title、summary、originalPrice、discountPrice、discountPercent、isDiscountAllowed、isPreSale、isPinned、publishTime、createTime、refreshTime、updateTime、isListed、status。

实测排除置顶后仍不是严格按publishTime倒序。因此当前正式测试客户端读取全部分页，检查authorId，筛选isListed=true、status=1、有publishTime的文章，按articleNo去重后再按publishTime降序取100篇。不使用createTime/updateTime/refreshTime替代发布时间。读取失败不更新基线，也不覆盖上次缓存。

2026-11-04实测：单个商家34页、3325篇在售文章，首次保留最近100篇耗时约9.5秒；随后两轮分别约7.9秒和8.6秒，均保留100篇，排序检查通过，无重复新增。大量商家监控时分页成本较高；在服务端排序参数核实之前，不以只读第一页的方式牺牲正确性。分页不是事务快照，扫描期间平台内容变化仍可能产生短暂偏差；两次轮询之间新增超过100篇也可能超出当前窗口。

## 文章排序与轮询测试命令

```powershell
# 查询关注商家及authorId
& 'D:\ProgramData\Anaconda3\envs\quant312\python.exe' '.\tests\料小宝文章监控测试.py'
# 单次取最近发布100篇
& 'D:\ProgramData\Anaconda3\envs\quant312\python.exe' '.\tests\料小宝文章监控测试.py' --author-id '商家authorId'
# 持续监控，一轮完成后等待60秒；Ctrl+C停止
& 'D:\ProgramData\Anaconda3\envs\quant312\python.exe' '.\tests\料小宝文章监控测试.py' --author-id '商家authorId' --watch
```

结果文件为程序目录的 `料小宝最近文章.local.json`，只保存监控所需的标题、ID、发布时间、价格和状态等字段，不保存付费正文、账号密码或登录密钥。第一次读取仅建立基线，不提示历史新增；后续按articleNo检测新增。

1. 先使用已保存的料小宝会话调用profile，确认没有过期；不向终端打印token、secret、iv。
2. 调用counts及关注列表第一页，将结果保存为本地测试文件；确认商家唯一标识authorId及名称字段，核对总数和分页。
3. 选一个关注商家，将其authorId传给文章列表接口；核对articleNo、标题、时间、价格、折扣、置顶等真实字段，并确认是当前在售、而非历史或下架数据。
4. 确认按发布时间排序的最近100篇加载方式，处理置顶和分页；先单独轮询测试无重复提醒，再接入统一工具。

可运行 `tests/料小宝商家监控测试.py`，默认仅验证本人资料、读取counts和第一页关注列表；用 `--author-id` 增加文章第一页测试。只使用程序中独立保存的料小宝用户监控会话，不读取商家发布会话。若失效，先在统一工具“料小宝用户监控登录”页重新登录；有多个监控用户时，通过统一界面选择账号，独立脚本不自动猜选账号。

测试文件 `料小宝监控测试.local.json` 位于程序目录，含本人资料和关注商家数据，请勿公开分享。密码配置不会被写入此结果。
