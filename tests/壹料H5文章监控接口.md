# 壹料 H5 商家文章监控接口

> 本文件保留早期测试过程。当前正式监控请阅读 [壹料/红料用户监控接口](../docs/壹料红料用户监控接口.md)。下文 planHistory 为历史接口，当前最新文章监控使用 expertLastPlan，不使用历史文章补充。

## 登录与认证

H5 入口为 `https://m.njyuelu.cn/#/`。登录和监控使用同一个 HTTP 会话。图形码和短信码由操作者输入。下列手机号和验证码均为占位示例。

### 1. 获取图形验证码

`GET https://yapi.njyuelu.cn/resource/app-do/kaptcha?key=13800000000?1`

响应体是图片二进制。查询参数 `key` 的值为「手机号 + 问号 + 刷新序号」，第一次取图用 `1`，每次换图加一。校验时使用当前图片对应的完整 `key`。

### 2–5. 调用统一业务入口

以下四步都使用 `POST https://yapi.njyuelu.cn/h5/h5-do/common`。表中参数是加密前的业务对象。

| 步骤 | 业务路径 | 业务参数 | 成功判定 |
|---|---|---|---|
| 2. 校验图形码 | `/resource/app-do/kaptchaValidate` | `{"d":{"code":"0123","key":"13800000000?1"}}` | `c: 200` 且 `d: true` |
| 3. 发送登录短信 | `/resource/rse-sms-do/sendCode` | `{"d":{"phone":13800000000,"code":1}}` | `c: 200`，已观测到 `d: null` |
| 4. 短信登录 | `/user/usr-do/login` | `{"d":{"phone":13800000000,"smsCode":"012345"}}` | `c: 200`，从 `d.token` 取令牌，从 `d.userId` 取登录用户 ID |
| 5. 查询本人资料 | `/user/usr-do/userInfo` | `{"d":{}}` | `c: 200` 且 `d.id` 等于登录返回的 `d.userId` |

`phone` 在发短信和登录请求中是数字，两个验证码都是字符串。发短信时的 `code: 1` 是登录业务类型。登录响应还观察到 `accessCode`、`phone`、`type`、`first`、`token2`。当前脚本用 `token` 验证会话。

统一入口请求使用 JSON。设表中的业务路径为 `uri`，业务参数对象为 `body`，则先将 `{"uri": uri, "d": body}` 序列化为紧凑的 UTF-8 JSON。使用脚本内的 RSA 公钥按 PKCS#1 v1.5 加密，每段最多 117 字节。拼接密文并做 Base64 编码，最终提交 `{"m":"<Base64 密文>"}`。

脚本发送以下请求头：

| 请求头 | 值 |
|---|---|
| `Content-Type` | `application/json` |
| `Origin` / `Referer` | `https://m.njyuelu.cn` / `https://m.njyuelu.cn/` |
| `appId` / `version` | `yl-m` / `1.0.0` |
| `uuid` | 本次运行生成的 UUID，流程内复用 |
| `h5url` | 当前业务路径 `uri` |
| `paramUrlData` | URL 编码后的业务参数 `body` 的紧凑 JSON |
| `Authorization` | 第 4 步成功后填入原始 `d.token` |

响应是普通 JSON，`c` 为业务码，`m` 为提示，`d` 为业务数据。每步成功后再继续下一步。只验证登录时运行 `python .\\tests\\壹料H5登录测试.py`。登录会话由测试进程持有，进程结束后重新运行需再次登录。

## 查询文章列表

- HTTP 方法及地址：`POST https://yapi.njyuelu.cn/h5/h5-do/common`
- 业务路径：`/plan/app-plan-do/planHistory`
- 请求头：`Authorization` 填登录返回的 token，`h5url` 填业务路径，`paramUrlData` 填 URL 编码后的业务参数 JSON。沿用登录会话的 `appId`、`version` 和 `uuid`。

封装前的业务参数示例：

```json
{
  "d": {
    "data": {
      "expertId": "DL20260506121136970JCUD",
      "sportsId": 4,
      "groupType": "",
      "labelId": "",
      "title": ""
    },
    "page": 1,
    "pageSize": 15
  }
}
```

`expertId` 是商家的专家 ID。`sportsId: 4` 沿用本次店铺抓包，仅代表已确认的查询分类。

线上请求体为 `{"m":"<Base64 密文>"}`。加密前 JSON 的外层是 `{"uri":"<业务路径>","d":<上述业务参数>}`。复用登录测试脚本的 `common()`，按 RSA PKCS#1 v1.5 分段加密，再对拼接后的密文做 Base64 编码。

## 响应与监控

成功业务码为 `c: 200`，文章在 `d.rows` 中，接口报告的总数在 `d.total` 中。

| 字段 | 含义 |
|---|---|
| `planId` | 文章 ID，用于去重 |
| `planTitle` | 标题 |
| `planPublicTime` | 发布时间 |
| `expertId` | 商家专家 ID |
| `price` / `priceReal` | 原价 / 接口返回的实际价 |
| `noDiscount` / `discount` / `priceDiscount` | 折扣相关字段，打折样本待核对 |
| `top` | 置顶状态 |

首次读取第 1 页，最多 15 条作为历史基线。之后默认每 60 秒查询同一页，按本次运行已见过的 `planId` 去重。检测到新 ID 时输出文章，按 Ctrl+C 停止。去重记录仅保存在进程内。两次轮询之间挤出第一页的文章可能漏报，旧文章重新进入第一页也可能被提示为首次发现。

```powershell
conda activate quant312
python .\tests\壹料H5登录测试.py --expert-id DL20260506121136970JCUD --watch
```

登录和本人资料查询已实测通过。文章列表参数来自网页抓包，持续轮询的新帖识别仍待实测。
